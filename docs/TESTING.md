# Проверка сборки

## Автоматические тесты

`./tools/run.ps1 test` запускает `tests/test_runner.gd` на том же Godot 4.5.2, что используется для экспорта.

Текущий результат: **341 проверка, 0 ошибок**; симуляция первого боя на 100 RNG seeds — **100 побед** при тестовой стратегии. Это проверка работоспособности и проходимости, не оценка качества боевого баланса живыми игроками.

Проверяются:

- Загрузка каталогов, неверные типы и неизвестные команды.
- Порядок квестовых шагов, фильтрация чужого боя, одноразовый ларец и награды.
- Требование ключа для прохода через врата.
- Запись/чтение, резервный файл при повреждении основного, миграция v1 → v2.
- Отрицательное здоровье, неизвестные персонажи, будущая версия, некорректные координаты/уровни.
- Недопустимые цели без расхода маны, недоступная командная атака, защита, недостаток MP, отказ лечить павшего предметом.
- Завершение боёв, получение опыта и наград.
- Настоящая главная сцена: вступление → квест → бой → финал → повторная загрузка финала.

Тестовая главная сцена перенаправляет сохранения в `user://test_saves`, не в игровые `user://saves`.

## Браузер

После экспорта запустите сервер и `node tools/test-web.cjs` с доступным пакетом Playwright. На текущем компьютере он установлен в bundled Node runtime; при самостоятельном использовании установите Playwright как dev dependency.

Сценарий использует реальный Chrome с WebGL2 и проверяет загрузку WASM, клавиатуру/мышь, переходы, изменение размера 1280×720 → 390×844, касание кнопки выбора навыка, наличие корректного снимка в IndexedDB и продолжение после перезагрузки. Сохраняет `artifacts/web-report.json` и PNG-снимки.

Бой до победы проверяется нативным интеграционным тестом. Браузерный сценарий пока проверяет вход в бой и выбор цели, а не все раунды. Снимки просматриваются отдельно; сам сценарий не является pixel-diff тестом.

## Ручной device checklist

- [ ] iPhone/Safari: первый запуск по HTTPS, звук после касания, поворот, sleep/resume, сохранение после перезапуска.
- [ ] Android/Chrome: физические касания, удержание D-pad, расход памяти, время загрузки.
- [ ] iPad/tablet: размер кнопок и safe areas.
- [ ] Геймпад: стик/D-pad, A, фокус команд и возврат из меню.
- [ ] Длинные локализованные реплики, все выражения портретов после замены ассетов.
- [ ] 60 FPS и память на целевых устройствах; F3 полезен для первичного мониторинга, но не заменяет profiler.
- [ ] Production hosting: HTTPS, `application/wasm`, HTTP Brotli/gzip, cache versioning.

Не считать эмуляцию размера экрана проверкой настоящего телефона. В автоматическом Chrome используется программный рендеринг, поэтому его FPS не отражает производительность телефона или обычного desktop GPU.
